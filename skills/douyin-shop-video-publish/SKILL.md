# 抖店短视频自动发布（Agent Skill · 可配置版）

## 零、安装与配置（部署者必读）

### 0.1 环境依赖

| 依赖 | 说明 |
|---|---|
| 支持 Agent Skills 的客户端 | 将本技能目录（含 SKILL.md）放入客户端 skills 根目录即可被识别 |
| 浏览器自动化 | 豆包浏览器 / `computer_use_tool`（plane=bu，`seed_browser_use`） |
| Python 3 + openpyxl | 读取本地违禁词表 / 商品ID.xlsx（可选，页面可替代部分功能） |

### 0.2 安装步骤

1. **获取技能**：将本仓库 `skills/douyin-shop-video-publish/` 整个目录复制到客户端的 skills 根目录；
2. **新部署者请先读 `CONFIG-GUIDE.md`**（同目录），按其中「第一步→第七步」手把手完成安装与配置（约 15 分钟）；
3. **执行 Agent 请以 `AGENT-GUIDE.md` 为操作协议**（同目录）：含每步输入/输出、工具调用、JS 片段、判定与暂停条件、回填与断点续跑——本文件只给业务方法论；
4. **创建配置**：复制 `config.example.json` 为 `config.json`（与 SKILL.md 同目录），按「一、配置项说明」填写；
5. **准备资产**：按配置路径放置违禁词表（xlsx）与商品ID表（xlsx 或腾讯文档）；
6. **登录**：按 0.3 完成抖店 / 任务表平台登录；
7. **验证**：运行一次「全表扫描」（见「二、1」）确认能读到任务表，即部署成功。

### 0.3 登录流程（调用时引导，不保留登录状态）

> 技能**内置**任务表 / 商品ID表 / 违禁词表地址（见 config.example.json），但**不保存任何登录状态**（无 cookie、无 token、无自动登录）。每次调用时由 Agent 现场引导登录：

1. **抖店**：打开 `pages.home` → 未登录则引导企业微信扫码登录 → 确认右上角可见店铺名与「切换组织/店铺」；
2. **任务表/商品ID表（腾讯文档）**：打开内置链接 → 未登录则引导用户登录（扫码/账号）→ 确认能读取数据（`window.SpreadsheetApp...` JS API）；
3. 登录完成后仅本次会话有效，**不写入任何文件、不持久化**；下次调用需重新登录（Agent 会再次引导）。

### 0.4 安全与分享

- **技能内置真实业务链接**（任务表/商品ID表/违禁词表地址），这些是资源地址而非凭据；打开后需登录才能看内容；
- **不保留登录状态**：任何调用都不保存 cookie/token/密码，登录仅当次会话有效；
- 分享给他人时，对方打开内置链接仍需其自己账号的文档权限；请自行评估分享范围，必要时可将链接替换为对方自己的文档；
- 分享时只分享本技能目录（SKILL.md + config.example.json + 引导文档），不包含登录凭证与运行历史。

## 一、配置项说明（config.json）

所有私有信息一律放 `config.json`（模板见 `config.example.json`），字段：

| 配置键 | 说明 | 示例 |
|---|---|---|

| `sheets.task_sheet_url` | 任务表（腾讯文档）URL | **已内置**（config.example.json 默认值，可覆盖） |

| `paths.video_dir` | 视频暂存目录（**相对路径默认=技能目录下 `video_tmp/`**，与技能保存在一起便于整理；支持绝对路径覆盖；**不存在时询问用户是否创建**，不直接报错缺失） | `./video_tmp`（内置） |
| `paths.banned_words_xlsx` | 违禁词表（本地 xlsx，也支持在线链接） | `D:\douyin_shop_video_publish\违禁词表.xlsx`（内置） |

| `paths.run_log_dir` | 运行记录目录 | 私有 |

| `rules.max_concurrency` | 店铺并发数 | `2` |
| `rules.huan_yihuan_max` | 违禁词换一换上限 | `5` |
| `rules.timed_hours_gap` | 同店相邻视频发布时间间隔（小时） | `2` |
| `rules.publish_window` | 当天允许的发布时间窗口（空=不限） | 私有 |
| `rules.archive_keep_days` | 已发布视频归档保留天数，超过自动清理（0=发布后即删，不做归档） | `30` |

## 二、核心执行流程

### 1. 启动：全表扫描（防遗漏纪律）

- 用 JS API 读取任务表（禁用硬编码行区间）：
  ```js
  window.SpreadsheetApp.workbook.worksheetManager.getSheetList()[0].getCellDataAtPosition(r, c)
  ```
- 列映射（默认，可在 config 扩展）：c0=A 视频名（超链接在 `cell.value.r[].hyperlink.url`）、c3=D 店铺、c4=E 发布时间、c5=F 备注；E 行号 = 数据行号 + 1。
- 遍历 0→真实末行，按店铺列分组，建立每店完整任务清单（行号+视频名+发布时间+备注）。
- 识别：已完成（E 有值跳过）、待处理（E 空且非跳过）、测试行（备注含「测试」跳过）、违规视频（备注含违规跳过）。
- 每店处理前后都重新全表扫描一次，确认无新增、回填生效。

### 2. 店铺队列与并发（店铺清单跟随用户，不写死）

- **店铺清单来源（动态发现，优先）**：任务表 D 列去重得到「任务店铺集合」，并读取抖店登录账号实际可访问店铺（首页 → 右上角店铺名 → 「切换组织/店铺」弹窗 → 枚举全部可选店铺）得到「账号店铺集合」。
  - 任务店铺 ∈ 账号店铺 → 纳入队列，正常处理；
  - 任务店铺 ∉ 账号店铺 → **该店暂停人工处理**（提示：该店铺不在当前登录账号下，请切换到对应账号或更换账号，完成后点「我已完成」），不猜测、不跳过。
- **新增店铺询问（当前仅单个店铺时）**：若任务表存在未发布任务的店铺 X，而当前处理店铺集合**只有 1 个店铺 Y（X≠Y）** → **暂停并询问用户**：「任务表中有店铺 X 的视频未发布，当前仅处理店铺 Y，是否将 X 新增为处理店铺？」
  - 用户答「是」→ 将 X 纳入本次处理清单，继续执行；
  - 用户答「否」/「不用」→ **停止处理该店 X**（本次不发布 X 的任何视频），并把用户习惯记录到当日运行记录（如「用户选择暂不处理店铺 X」）；**后续运行遇到 X 默认沿用该习惯不再询问**，直到用户明确说「新增店铺 X」才解除并处理。
- `config.json` 的 `shops` 为**可选白名单**：留空（默认）= 完全跟随登录用户自动发现；填写 = 仅处理白名单内店铺（对任务表 D 列过滤）。
- 并发单位 = 店铺，默认并发 `rules.max_concurrency`（可配置 1-5）。
- 同店严格按任务表顺序串行；不同店可并行。
- 每店独立维护：登录态、任务、发布数量、发布时间、异常状态。

### 3. 店铺切换（已验证路径）

- 必须在**首页**操作（短视频运营页无入口）。
- 点击右上角店铺名区域（含头像+店名+箭头，约坐标 940,30）→ 弹出店铺信息侧栏 → 点击「切换组织/店铺」→ 弹出「请选择店铺」列表（可见约 4 家，下方需滚动）→ 点击目标店铺。
- 切换后验证页面右上角店铺名 = 目标店铺。
- 若子账号无首页权限：短视频运营页权限正常，直接导航即可，不影响发布。

### 4. 挂车额度确认

- 进入短视频运营页，读取「今日挂车短视频可发 N/M 条」。
- 额度以页面实际显示为准，不询问用户、不自设上限。
- **规则**：当天有挂车额度就用挂车模式发完；发完当天挂车额度后**不再发布非挂车视频**（剩余任务延期，下一次运行继续）。

### 5. 视频下载与文件生命周期

- 从任务表 A 列超链接取微盘地址，打开 → 点「下载」按钮 → `bu.wait_for_download` 拿到完整文件（禁止把 `.crdownload` 当完成）。
- **视频工作目录检查（`paths.video_dir`）**：`video_dir` 为相对路径时以**技能目录（SKILL.md 所在目录）**为基准解析。目录不存在 → **询问用户是否创建该目录**（提示：`paths.video_dir` 不存在，是否创建？）——用户同意 → 创建目录后继续；用户拒绝/不确定 → 暂停人工处理。**不得直接报「目录缺失」中断**。
- 下载前检查本地是否已存在同任务文件（存在且完整则复用）。
- 命名：`店铺名_日期_原名`；AI 作品文件名含 `_AI`，**不得自行猜测 AI 属性**。
- 移入 `paths.video_dir`（进行中文件放目录根，不混入归档）。

**发布后归档与定期清理（方案 B，默认启用）**：
- 视频**发布成功且任务表回填验证通过后**，把该视频文件移动到 `paths.video_dir/archive/`（归档子目录不存在则创建），避免堆积在暂存根目录。
- 每次运行**开始时**清理归档目录：删除修改时间超过 `rules.archive_keep_days` 天（默认 30）的文件；清理结果记入当日运行记录。
- `rules.archive_keep_days=0` 时：发布成功后直接删除该视频文件（不归档、不保留），等同方案 A。
- 归档目录里的文件**不参与断点续跑判断**（已发布+回填=任务完成，绝不重发）。

### 6. 上传（挂车面板）

- 短视频运营 → 「单独发视频」→ 挂车模式。
- `bu.upload_file("input[type=file]", 本地绝对路径)`；等待上传 100%、出现封面推荐即完成。
- 页面重渲染会失效 refs / input[type=file]，需重走面板；`upload_file` 用 selector。

### 7. 商品匹配（禁止猜测）

- 商品ID本地表 / 在线表（含型号→编号→话题）→ 发布面板「选择商品」。
- 商品查询：按「商品名称」label 定位父容器 input（原生 setter + input/change 事件）→ 点真 `button[type=submit]`「查询」。
- **唯一匹配** → 自动勾选 radio → 确认「已选商品（1/1）」→ 确定。
- **多匹配** → 暂停人工处理，列出匹配项请用户选择；**无匹配** → 人工处理（用户指定编号或按异常流程）；禁止随机选择。
- 多店铺数据隔离：不同店铺同型号商品编号可能不同，以本店实际查询结果为准。

### 8. 标题与作品描述

- 优先使用平台 AI 自动生成（小黄车标题 + 作品描述），必须等待生成完成；未生成才自行生成，不得留空。
- 生成慢不算失败，继续等待。
- **标题末尾添加任务编号（2026-10-14 新增，强制）**：标题（小黄车标题与抖音标题）确定后，打开智能表格「视频组PPV」`https://doc.weixin.qq.com/smartsheet/s3_AfEAVQZuAM0CNPuBBXNwHTn0dsbb6?scode=AHsABQd8AA4g1DAjlDACQAFgaXAJg&tab=thGrIK&viewId=v4MZys`，确认当前视图为「明细表」，按**当前视频名称**（与任务表 A 列一致）查询「任务编号」列，在标题**末尾**追加「_任务编号」（4 位编号带下划线，如任务编号 0209 → 标题末尾加「_0209」）；查不到任务编号 → 不得猜测，按异常流程人工处理。

### 9. 违禁词检查与换一换

- 对照 `paths.banned_words_xlsx`（典型违禁：超、最、第一、顶级、必备、神器、微信、特有、极速、秒杀等；**「顺手」「太方便」「超市」「商超」（超市类）「超广角」不违禁（2026-10-19 用户确认排除，含「超」但属合规词）**——以实际表为准）。
- 有违禁 → 点描述区「已为你生成作品描述」内的「换一换」（div/span 文本元素，非 button）。
- **最多自动换一换 `rules.huan_yihuan_max` 次（默认 5）**；达到上限后仍含违禁 → **停止自动换一换**，按新规则：
  1. 打开商品ID在线表，**全表扫描**（探测真实维度，如 `_Md`），查该型号话题栏；
  2. 找到对应话题 → 用其替换描述话题（按 SOP 方式添加）；
  3. 找不到 → 进入人工处理，请用户提供合规话题或处理方式。
- 禁止超过配置上限的换一换次数。

### 10. AI 内容声明

- 文件名含 `_AI` → 点「无需添加自主声明」→ 选「内容由 AI 生成」。
- 不含 `_AI` → 跳过。

### 11. 话题添加（SOP，强制）

- **必须**：输入「#话题名」→ **等待下拉选项出现** → **选择第一个匹配选项** → 话题成为可识别标签（DOM 中为 `topicItem` 元素）才计入成功。
- 禁止把 `#+话题` 当纯文本一次性输入（不生效）。
- 非挂车流程：每条视频随机 3-5 个话题，至少成功 3 个；挂车流程 AI 生成的描述话题为有效标签（topicItem），核验后无需手动添加。
- **【强制·话题来源规则（2026-10-13 新增）】**：添加话题前，**必须先**打开商品ID在线表（或本地商品ID表），按「店铺+型号/编号」定位该商品所在行，浏览其**话题板块**：话题列从「话题」表头开始**横向延伸**，**每个单元格 = 一个话题**，读取该行话题列全部单元格。
  - **优先从商品ID表提取 5 个话题添加**；该商品 ID 话题数 > 5 → **随机选择 5 个**添加；< 5 → 全部使用后，再从「用户提供 → 商品相关合规词」补齐（非挂车至少成功 3 个）。
  - 提取出的话题仍必须逐个按 SOP 添加（输入 #话题 → 等待下拉 → 选第一个匹配 → 成为 `topicItem` 标签），**禁止把话题文本当纯文本一次性输入**。
- 话题来源优先级：**商品ID表话题板块（强制优先）** → 用户提供 → 商品相关合规词。

### 12. 发布时间（平台时间优先）

- 时间基准：Windows 本机当前时间；每店独立计算。
- 当天该店第 1 条 → **立即发布**；第 2 条及后续 → 上一条该店平台发布时间 + `rules.timed_hours_gap` 小时 → **定时发布**。
- 抖店定时限制：仅支持未来 2 小时-14 天；输入计算时间后**以平台实际显示/调整时间为准**（早于最早可定时 → 平台自动调整为最早可用）。
- 下一条计算时间超过当天允许窗口（`rules.publish_window`）→ 停止该店当天剩余任务（延期），不强行发布、不自改时间。
- 回填时间 = **发布成功后的平台显示时间**（不是点击发布的时刻）。

### 13. 发布前最终检查（缺一不点）

店铺正确 / 任务仍是目标任务 / 任务表未被其他进程完成 / 视频正确且已上传完 / 商品正确 / 标题与描述存在 / 违禁词已处理 / AI 声明正确 / 话题满足要求 / 发布时间正确 / 页面仍是发布页 / 无阻挡弹窗。任何一项无法确认 → 不点击发布。

### 14. 发布与成功判定

- 点击发布（`button[id=publishBtn]`）后**不能直接判定成功**。
- 成功判定：页面出现「已提交发布」弹层 **且** 视频管理列表出现新记录（含审核中/审核通过/定时发布中 + 平台发布时间 + 商品 + 视频ID）。
- 网络错误/无反馈/长时间加载等无法确认 → 异常处理，不得写成功。
- 普通技术错误最多重试 3 次（每次重试前重新检查页面状态）；3 次仍失败 → 状态=发布失败并记录原因和重试次数，继续其他任务。

### 15. 任务表回填

- 只有发布成功后才回填：名称框跳转 E 列（如 E415）→ F2 → `alloy-simple-text-editor` 输入 `2026/9/28 13:21` 格式 → 回车 → **JS API 回读验证保存**。
- 注意：直接调 `setCellDataAtPosition` 不持久化，必须走 UI 编辑路径。
- 回填后及时保存；不得等全部任务完成后才回填。
- **回填/清除安全流程（2026-09-29 事故后强制）**：① 先 JS API 备份整表到本地；② 名称框跳转目标格（验证名称框显示值）；③ F2 后确认焦点在编辑框；④ 输入用 execCommand('insertText') 或 bu.type(编辑框 ref)；清除内容同样用 insertText('') 替换全选（勿用 delete 键/Ctrl+A）；⑤ 回车提交后立即回读验证目标格±1 行；⑥ 编辑器异常（未提交/文本空/选中偏移）→ 停止并人工确认。

## 五、默认业务规则（可在 config.rules 覆盖）

1. 登录页/短视频运营页自动确认挂车额度，不每次询问用户；
2. 测试视频无需发布（任务表备注含「测试」）；
3. 有违规提示的视频不发布；
4. **当天有挂车额度就用挂车模式发完，发完当天不再发布非挂车视频**；
5. **定时发布时间以平台实际接受/显示时间为准；回填时间 = 发布成功后的平台时间**；
6. **换一换达上限仍违禁 → 先查商品ID表话题栏（全表扫描）→ 找不到对应话题再进入人工处理**；
7. 每处理完一个店铺先总结并记录遇到的问题和解决方法；
8. **启动时自动读取最近一次正确运行的记录**（`paths.run_log_dir` 下最新 `YYYY-MM-DD运行记录.md`），优先复用其中已验证的正确步骤与问题解决方法，而不是每次重新计算；
9. **新增店铺询问**：任务表存在未发布任务的店铺 X，而当前仅处理 1 个店铺 Y（X≠Y）时 → 暂停询问是否将 X 新增为处理店铺；用户拒绝则停止处理该店 X 并把习惯写入运行记录，后续运行沿用该习惯不再询问，直到用户明确表示新增店铺 X；
10. **视频工作目录缺失处理**：`paths.video_dir` 不存在 → 询问用户是否创建（同意则创建后继续；拒绝/不确定则暂停人工处理），不直接报错缺失；
11. **发布后归档与定期清理（方案 B）**：视频发布成功且任务表回填验证通过后 → 移入 `paths.video_dir/archive/`；每次运行开始时清理归档中超过 `rules.archive_keep_days` 天（默认30）的文件；`archive_keep_days=0` 则发布成功后直接删除（方案 A）。归档文件不参与断点续跑。
12. **违禁词排除词（2026-10-19 新增，用户确认）**：「超市」「超广角」**不属于违禁词**（虽含「超」字），违禁词检查时不得判定为违禁；与「顺手」「太方便」同为已确认排除词。
12. **回填/清除单元格前必须先备份整表**（JS API 读 A/D/E/F 全部行存本地文件），再执行写入/清除；
13. **禁止用 Ctrl+A+Backspace/Delete 清除单元格内容**（焦点不在编辑框时会选中整个表格并清空全表）；清除单元格：F2 → 确认 document.activeElement 是编辑框（#alloy-simple-text-editor/.formula-input）→ JS 全选编辑框内容（Range.selectNodeContents+selection.addRange）→ **execCommand('insertText', false, '') 替换选区（触发 input 事件，实测有效；execCommand('delete') 无效）** → Enter 提交 → 回读验证；
14. **每次单元格写入/清除后立即 JS API 回读验证目标格±1 行**；Enter 后编辑框仍打开且文本空 = 未提交 → Esc 取消后重新 F2，禁止在同一编辑器上连续叠加输入/方向键；定位优先名称框跳转（bar-label 输入+Enter）并验证显示值。
15. **阻塞问题即时沉淀（强制）**：每次遇到阻塞问题（人工处理、页面异常、误写/误操作事故、无法自动判断、登录态丢失等），在问题**解决后第一时间**把「问题现象 → 根因 → 解决方式 → 防再犯措施」总结写入当日运行记录与「四、问题与解决记录」，**然后再继续未完成的任务**；不得跳过沉淀直接继续，防止同类问题下次重现；沉淀后再继续可复用已验证步骤，避免重蹈覆辙。
16. **腾讯文档回填统一路径（2026-09-30 云端实测）**：① 名称框 = `input.bar-label`（左上角 @8,150），**严禁**输入到 `.melo-doc-title`（文档标题框，会改标题）；② 名称框跳转用 **bu 真实键盘**（click ref → ctrl+a → `bu.type(ref,"E{数据行+1}", submit=True)`），JS 派发 Enter 无效；③ 跳转后验证 nameBox 显示目标地址；④ `bu.press_key("Enter")` 进入编辑态 → 确认 `#alloy-simple-text-editor` 出现；⑤ JS `focus → selectNodeContents 全选 → execCommand('insertText', false, '时间')` 输入；⑥ `bu.press_key("Enter")` 提交；⑦ JS API 回读验证目标行 E 值±1 行。**禁止**在顶部公式栏（.formula-input）输入后直接提交（无效）；**禁止**坐标双击定位单元格（视图滚动会偏移到错误单元格）。
17. **话题来源强制规则（2026-10-13 新增，2026-10-17 强化）**：添加话题前**必须先浏览商品ID表（在线或本地）中该商品（按店铺+型号/编号定位）的话题板块**——话题列从「话题」表头开始**横向延伸**，**每个单元格=一个话题**，读取该行全部话题单元格；**优先提取 5 个话题添加**（>5 随机选 5；<5 全部使用后按「用户提供→商品相关合规词」补齐）；提取话题仍按 SOP 逐条添加（#话题→下拉→选第一个匹配→topicItem），禁止直接粘贴话题文本。**AI 生成话题强改规则（2026-10-17 用户指令，强制）**：无论平台 AI 生成的作品描述/标题中**是否已自动生成话题**，话题一律**以商品ID表该商品的话题词为准**——AI 自带的话题必须被替换/忽略，不得保留 AI 随机生成的话题；若 AI 未生成话题，则直接添加商品ID表话题；最终生效话题必须全部来自商品ID表对应商品的话题词（按上述 5 个/补齐规则执行）。示例：某型号商品的话题词（具体以商品ID表实际查询为准）= 飞鹅打印机 / 飞鹅外卖打印机 / 飞鹅外卖自动接单打印机 / 外卖打印机。
18. **标题末尾添加任务编号（2026-10-14 新增，强制）**：标题（小黄车标题与抖音标题）确定后，打开智能表格「视频组PPV」（`https://doc.weixin.qq.com/smartsheet/s3_AfEAVQZuAM0CNPuBBXNwHTn0dsbb6?scode=AHsABQd8AA4g1DAjlDACQAFgaXAJg&tab=thGrIK&viewId=v4MZys`），确认当前视图为「明细表」，按**当前视频名称**（与任务表 A 列一致）查询「任务编号」列，在标题**末尾**追加「_任务编号」（4 位编号带下划线，如任务编号 0209 → 标题末尾加「_0209」）；查不到任务编号 → 不得猜测，按异常流程人工处理。
19. **首页无权限忽略、全部走左侧任务栏短视频运营入口（2026-10-17 新增，强制，适用所有店铺）**：任何店铺的账号只要出现「首页」无权限提示（「抱歉，你所属的岗位没有访问该页面的权限」权限点:首页），**直接忽略首页权限问题，不视为阻塞**，**禁止**在首页反复乱跳寻找切换入口；统一改为：从**左侧任务栏「流量 → 短视频运营」**进入短视频运营页完成发布（该页权限正常）。**注意：忽略「首页无权限」不等于忽略店铺切换**——店铺切换必须按规则20 强制执行（右上角路径），不得因首页权限问题跳过店铺校验。
20. **店铺切换为强制操作（2026-10-17 新增，强制，适用所有店铺）**：每个店铺开始处理任务前，**必须**通过**右上角店铺名区域（含头像+店名+箭头）→ 点击弹出「店铺信息」侧栏 → 点击「切换组织/店铺」→ 在「请选择店铺」弹窗中选择目标任务店铺**，切换完成后**必须验证右上角店铺名 = 目标任务店铺**，确认正确后才允许进入短视频运营页发布。**禁止**：因首页无权限、页内无切换入口、当前店铺名看似正确等原因跳过或省略该强制切换步骤；**禁止**在未切换/未校验店铺正确的情况下直接发布。若右上角切换入口不可用或目标店铺不在当前账号可访问范围内 → 暂停该店人工处理，明确提示用户「当前问题=店铺不在账号下/无法切换、当前页面、需要用户做什么（切换账号或店铺）、完成后点『我已完成』」，**不猜测、不跳过**；该店暂停不影响其它店铺。
21. **同一视频禁止重复发布两次（2026-10-17 新增，强制，防重复发布红线强化）**：任何一条视频**仅允许发布一次**，禁止因任务表状态异常、回填遗漏、断点续跑、发布结果未确认、页面刷新重试等原因对同一视频进行第二次发布；每次准备发布前，**必须**重新全表扫描任务表 + 核对抖店视频管理列表，确认该视频名称（含任务编号/标题）在任务表 E 列无发布时间且管理列表无同名新记录，才允许发布；若确认已在任务表回填或管理列表存在同名记录（无论状态），一律跳过并记录「已发布，防重复跳过」，不得重复上传/发布/回填。
22. **已验证方案优先执行（2026-10-19 新增，强制，用户拍板）**：执行**每一步**操作前，必须先查「三、已验证的操作细节」「四、问题与解决记录」及最近运行记录中该步骤是否已有**已验证的正确方案**：
   - **有已验证方案 → 必须直接按该方案执行**，禁止再次尝试已证明失败或低效的路径，也禁止用「再试一次」的心态在同一路径上反复消耗轮次；
   - **无已验证方案 → 才允许探索新方法**，成功后**必须**立即沉淀到「四、问题与解决记录」（问题→根因→解决→防再犯），供后续直接复用，不得每次重新摸索；
   - 已确认的反例（禁止重复尝试）：话题添加下拉选中（click/JS/键盘均失败，**直接用 JS 注入 topicItem 节点**）；上传卡进度（**直接刷新页面重传**，禁止在同一路径长时间等待）；回填（**统一走 名称框跳转→F2→#alloy-simple-text-editor→insertText→Enter→JS API 回读**，禁止公式栏提交/坐标双击）；商品编号输入（**只填第二个「请输入」框=商品编号框**，勿填商品名称框）；
   - 目的：杜绝重复消耗执行轮次与时间，防止任务因单次执行轮次耗尽被强制中断而留尾巴。
23. **断点兜底与进度落盘（2026-10-19 新增，强制，用户拍板）**：为应对单次执行轮次耗尽/异常中断，每条视频任务在处理过程中**每完成一个关键里程碑立即落盘**到运行记录目录的当日进度文件（`YYYY-MM-DD_进度.json`），记录：店铺、任务数据行号、视频名、任务编号、当前阶段、本地视频文件路径、回填格号（E列）、平台发布时间、视频ID、管理列表标题关键词。
   - 阶段定义：待处理 → 已下载 → 已上传 → 商品已挂载 → 标题完成 → 话题完成 → AI声明完成 → 已发布（待回填）→ 已回填 → 已归档；每完成一步立即更新进度文件。
   - 恢复判定优先级：**①进度文件**（定位断点阶段）→ **②任务表 E 列**（有值=已完成跳过）→ **③抖店管理列表同名记录**（有=已发布，只补回填不重发）→ **④本地视频文件**（存在=已下载可复用）。
   - 轮次耗尽被强制收尾 = **正常断点**，不视为失败，不报「发布失败」；下次触发先读进度文件，从断点阶段继续，禁止从头重做、禁止重复下载/上传/发布。
   - 任何阶段恢复时，若无法确认上一步已完成（如无法确认上传完成/无法确认是否已发布）→ 按防重复规则先核对管理列表：有同名记录 → 跳过并只补回填；无同名记录且上一步不可确认 → 暂停人工处理，**不得直接重发**。
   - 发布成功 = 回填 + 归档 + 进度文件标记「已归档完成」三件事都完成，任务才算闭环；进度文件是中间态，最终以任务表 E 列 + 管理列表为准。
